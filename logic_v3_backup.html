AlignedTable 读写全解

这个大方块就是一张逻辑表：竖条 = 列组（index / alpha101 / ma / alpha191）， 每条内部的小块 = part（parquet 文件）→ RG（行组）。
四个模式分别演示 读 · INSERT · UPDATE · DELETE，动画直接标在图上；悬停任意小块可看说明。

一、核心概念

🗂

Logical Table 逻辑表

cnstk_ixday 是一张逻辑表；目录即 Catalog——没有独立元数据库，_table.json 只是轻量清单。

🧱

Column Group 列组

图中每个竖条是一个列组，独立存 Parquet，物理布局可不同。

🔑

Key 只存一份

主键 (date, symbol) 只在 index 组；其余组不重复存键。

↔️

Logical Row Space

所有组按行号严格对齐：index[N] == alpha[N] == ma[N]。同色 RG 跨组等高就是对齐的可视化——查询绝不 JOIN。

📦

Part = Parquet 文件

文件名自描述行区间：0000-0000005998.parquet = 索引0000 · 5998 行。行区间由文件名推导，零 footer IO。

🧩

RG = Row Group

part 内部的最小读取单元（默认 16384 行），带 min/max 统计可整段跳过。index 下方的「追加/更新区」是新写入的落点，不参与跨组对齐展示。

三、ATTACH：让标准 SQL 直写列组

ATTACH '/data' AS al (TYPE ALIGNED); SELECT * FROM al.cnstk_ixday; -- 裸名查询，零物化 INSERT INTO al.cnstk_ixday (date, symbol, close) VALUES (...); UPDATE al.cnstk_ixday SET close = 123.4 WHERE symbol='009999'; DELETE FROM al.cnstk_ixday WHERE symbol='009999'; DETACH al; -- 数据始终在 parquet 列组目录里
标准 SQL→ Binder→ PlanInsert / PlanUpdate / PlanDelete 钩子→ Sink 算子→ mutator（upsert / delete）→ 只重写受影响 part → 原子提交
  • DuckLake 式逻辑 attach：表保持逻辑表，SELECT 走 aligned 扫描，不物化、不复制数据。
  • 写路径复用 mutator：INSERT/UPDATE 按 (date, symbol) upsert，DELETE 按键剔除，全部只重写受影响 part。
  • 只 SET 被修改的列：UPDATE 先解析 rowid→键，再按列组映射精确回写；schema-evolution 的老 part 不会被强制补列。
  • 读路径完好：投影 / 分区 / RG 三级剪枝对 catalog 表同样生效。
